# 履歴による部位おすすめ・120分対応

2026-11-27 / バージョン1.0.3、Android versionCode 4。

## 仕様

- サーバーでAIのメニューを検証した後、選択した部位と生成日時を記録して成功を返す。
- 選択した部位だけを記録し、AIが補助的に含めた部位や、種目の差し替えでは追加記録しない。
- 部位ごとの最後の生成から48時間未満を除外し、48時間ちょうどで候補に戻す。
- 記録なし→最後の生成が古い順に最大2部位。同順位は既存の部位一覧順。
- 候補がなければ「おすすめの部位はありません」。全6部位は手動でも選択可能。
- 起動・ホームへの復帰・アプリの前面復帰で履歴を読み直す。サーバー時刻を基準に経過時間を進め、画面表示中は30秒ごとに候補を再計算する。
- 履歴取得のエラーを「記録なし」と扱わず、再読み込みを案内。ログアウトやアカウント変更で別アカウントの履歴を表示しない。
- 休養・疲労の判定とトレーニング完了入力は追加しない。
- 時間は10〜120分、5分刻み、初期値30分。長い設定でも時間を埋めるための無理な増量はしない。

## 保存と互換性

`generated_training_history`は部位・生成日時の履歴。メニュー全体や重量・実績は保存しない。
RLSで本人の読み込みと挿入だけを許可し、クライアントが所有者や時刻を指定・変更する権限は与えない。
`get_training_history`で部位ごとの最終生成時刻とサーバー時刻だけを返す。
以前のAPIレスポンス形式を維持しているため、旧APKの生成もサーバー反映後から記録される。反映前の履歴は復元できない。

- 自動テスト47件、型チェック、lint：成功。
- Android・iOS・Webバンドル：成功。
- 実Supabase：マイグレーションと2つのEdge Functionを反映済み。
- 実Supabaseで本人の履歴保存・読み込み、複数部位の集計、未ログインからのアクセス拒否、記録時刻の変更拒否、125分の入力拒否を確認。
- 接続検証で作成した正確な1行だけを終了時に削除し、一時セッションもログアウト。実際のGeminiを呼ばずに検証。
- ユニットテストでAI失敗・不正回答・利用制限時の履歴非記録、成功時の記録順序、記録失敗時のエラー応答、120分の受付を確認。
- ブラウザで未ログイン時のおすすめ案内と、スライダーで120分を選べること・上限を超えないことを確認。[画面](screenshots/history-duration-120.jpg)
- ログイン後のおすすめのタップ操作・再起動後の表示はAndroid実機で別途確認。
